# 租户继承实现说明

> 本文档记录 BKFlow 多租户模式下的租户继承机制实现，确保子任务、子流程和嵌套引用正确继承父任务的租户信息。

## 概述

在多租户环境下，子任务需要从父任务继承租户信息，确保租户边界不被突破。租户继承覆盖以下场景：

- 子流程任务创建
- 子画布循环执行
- 嵌套模板引用
- 任务快照准备
- 异步回调处理

## 核心原则

1. **租户边界严格遵守**：子任务必须与父任务处于同一租户，不允许跨租户引用
2. **显式传递优先**：优先使用请求中明确传递的租户 ID
3. **上下文回退**：请求缺少租户信息时，从父任务上下文或空间归属恢复
4. **多租户强制**：开启多租户模式后，缺少租户信息直接拒绝，不回退为 `system` 或 `default`
5. **单租户兼容**：关闭多租户模式时，保留原有行为，允许省略租户字段

## 租户继承路径

### 1. 子任务创建时的租户继承

**实现位置**：`bkflow/contrib/api/collections/interface.py`

子任务创建请求通过 Interface 模块的内部接口准备任务信息，租户继承逻辑如下：

```python
def prepare_task_extra_info(self, data):
    """
    准备子任务的额外信息，包括快照、变量等
    
    data 参数应包含：
    - space_id: 空间 ID（必需）
    - template_id: 模板 ID（必需）
    - tenant_id: 租户 ID（多租户模式下必需，从父任务传递）
    - parent_task_id: 父任务 ID（用于审计和追踪）
    """
    # 实现包含重试逻辑，处理临时网络故障
    # 多租户模式下，Interface 会验证 tenant_id 与 space 的归属一致性
```

**继承流程**：

1. Engine 从父任务 `TaskInstance` 读取 `tenant_id`
2. 构造 `prepare_task_extra_info` 请求时显式传递 `tenant_id`
3. Interface 验证租户与空间归属一致性
4. 返回的快照和配置信息已包含租户上下文

### 2. 嵌套子流程的租户传递

**验证位置**：
- 模板引用校验：`bkflow/template/validators.py`
- 子流程执行：`bkflow.pipeline_plugins.components.collections.base`

**机制**：

```python
# 保存、调试和模板读取时检查嵌套引用
- 递归检查流程树中的子流程、子画布节点
- 验证引用的模板与当前空间属于同一租户
- 不同租户的空间不能相互引用模板（即使在同一租户内）
```

**约束**：

- 单租户模式：保留不传空间的旧内部请求和原有引用行为
- 多租户模式：
  - 子流程从父任务记录获取空间
  - 内部模板读取必须同时匹配模板 ID 和空间归属
  - 同租户的不同空间仍不能直接互相引用

### 3. 历史快照的租户绑定

**绑定规则**：

- MD5 历史版本绑定所属模板，不同模板即使内容相同也不串用版本
- 旧快照的 `template_id` 为空时：
  - 只兼容当前模板通过 `snapshot_id` 明确指向的快照
  - 不会全局查找未知归属的历史快照
- 多租户模式下，快照查询必须匹配空间租户

### 4. 异步任务的租户恢复

**实现位置**：Engine 任务上下文管理

**恢复路径**：

1. **任务创建时**：从已验证的空间归属写入 `tenant_id` 到 `TaskInstance`
2. **任务执行中**：从本 Engine 的任务记录读取租户信息
3. **回调处理时**：
   - 升级前已持久化的 Pipeline 上下文如果缺少租户
   - 远程插件、审批和通知从 `TaskInstance.tenant_id` 读取
   - 不批量改写运行中的 Pipeline 上下文

4. **历史周期配置**：
   - 缺少租户时，通过 Interface 内部接口查询空间租户
   - 无法查得时停止创建并记录错误，不猜测归属

## 快照准备重试机制

为避免临时网络故障中断子任务创建，实现了智能重试机制：

**特点**（PR #925, commit a68f788）：

```python
SNAPSHOT_MAX_ATTEMPTS = 3          # 最多重试 3 次
SNAPSHOT_RETRY_BUDGET = 30.0       # 总预算 30 秒
SNAPSHOT_CONNECT_TIMEOUT = 3.0     # 连接超时 3 秒
SNAPSHOT_READ_TIMEOUT = 10.0       # 读取超时 10 秒
```

**重试策略**：

- 仅对可重试错误（网络超时、临时故障）重试
- 业务校验失败（租户不匹配、权限不足）立即返回
- 指数退避：`2^attempt + random(0, 0.5)` 秒
- 保留 Trace ID 用于分布式追踪

**错误类型**：

- `SNAPSHOT_PREPARE_UNAVAILABLE`: 可重试，服务暂时不可用
- `SNAPSHOT_PREPARE_REQUEST_FAILED`: 不可重试，业务逻辑错误

## 存量数据兼容

### 回填命令

**命令**：`python manage.py backfill_tenant_ids`

**用途**：为升级多租户前的存量空间、任务和周期配置回填租户 ID

**使用方式**：

```bash
# 1. 预览（默认模式，不修改数据）
python manage.py backfill_tenant_ids --module interface --mapping /path/to/space-tenants.json

# 2. 实际执行
python manage.py backfill_tenant_ids --module interface --mapping /path/to/space-tenants.json --apply
```

**映射格式**：

```json
{
  "1": "tenant-a",
  "2": "tenant-b",
  "3": "system"
}
```

**注意事项**：

- 不要使用示例值，必须基于实际部署环境核实归属
- 不要未经核实将所有空间映射到 `system`
- 已有非 `default` 且不等于目标租户的记录会报错，禁止覆盖
- 需要在 Interface 和每个 Engine 数据库分别执行
- Engine 不查询 Interface ORM，也不会自动修改其他 Engine

### 在途流程兼容

**历史任务**：

- 升级前已持久化的 Pipeline 上下文缺少租户时：
  - 远程插件、审批、通知从 `TaskInstance.tenant_id` 读取回填后的租户
  - 不批量改写运行中的 Pipeline 上下文

**历史周期任务**：

- 缺少租户时通过 Interface 内部接口查询空间租户
- 无法查得时停止创建并记录错误
- 该后备路径要求 Interface 已先完成回填

## 单租户与多租户模式

### 配置开关

```python
# 环境变量（按优先级）
BKPAAS_MULTI_TENANT_MODE=false   # 新配置（优先）
ENABLE_MULTI_TENANT_MODE=false   # 旧配置（兼容）
```

### 行为差异

| 特性 | 单租户模式 | 多租户模式 |
|------|-----------|-----------|
| 空间创建 | 可省略 `tenant_id`，空字符串归一为 `default` | 必须提供 `tenant_id` |
| 任务创建 | 可省略租户 | 必须匹配空间租户 |
| 子流程引用 | 保留旧协议，不强制空间传递 | 必须同时匹配模板和空间归属 |
| 缺少租户 | 不调用用户服务，使用默认值 | 拒绝处理，不回退为 `system` |
| 插件请求 | 保留旧协议 | 请求前验证租户，缺少时拒绝 |
| 前端字段 | 不主动附加租户字段 | 附加并验证租户信息 |

### 切换注意

- 关闭多租户开关**不会**将已分属不同租户的数据重新合并
- 关闭开关**不是**多租户生产环境的回滚方案
- 保持单租户部署与多租户转单租户需分开处理

## API 入口约束

### Web 与 SDK 用户态

- 从登录用户身份读取租户
- JWT 用户租户必须与登录用户一致
- SDK 已认证应用的请求租户必须一致
- 列表、详情、批量操作均按空间归属约束

### APIGW 应用态

| 应用类型 | 租户要求 |
|---------|---------|
| 单租户应用 | JWT 中的应用租户；`X-Bk-Tenant-Id` 可省略，传入时必须一致 |
| 全租户应用 | 必须用 `X-Bk-Tenant-Id` 选择租户，并匹配目标空间 |

**约束**：

- 创建空间的 `tenant_id` 必须等于本次请求租户
- 通过模板或任务 ID 调用的接口检查真实所属空间
- 多租户下本地鉴权豁免不会跳过租户边界

### 模块与异步执行

- Engine 仅接受有效模块凭证，并按内部空间头约束任务
- Interface 只有显式标记的内部接口可使用模块身份
- Engine 不查询 Interface 数据库
- 多租户的 `ModuleInfo` 管理接口整体拒绝租户管理员访问
